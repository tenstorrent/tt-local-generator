Multi-step pipelines

Workflows — chain anything

String together FLUX images, SkyReels video, LLM text, and forge plugins into a single named pipeline. Run from the toolbar. Results land in a playlist. Watch in TT-TV.

⚙ Toolbar button ComfyUI-compatible JSON tt-ctl workflow run

The UI

One button, three zones

The ⚙ Workflow button lives in the main toolbar, next to TT-TV. Click it to get a compact popover: pick a spec, tweak parameters, see recent runs, hit Run.

1

Pick a spec

Choose from built-in workflows in docs/examples/workflows/ or drop your own JSON into ~/.local/share/tt-local-generator/workflows/.

2

Adjust parameters

Any prompt, seed, model, or guidance_scale that isn't a node-to-node wire appears as an editable field. Overrides write to a temp file — your spec is never mutated.

3

Run & watch

Hit ▶ Run. The progress label updates live as the pipeline moves through nodes. When it finishes, a → Watch button appears to open TT-TV for that run's playlist.

Example

1964 World's Fair pipeline

Nine nodes. Five prompts. Thirty artifacts. One playlist. Here's what each node does.

1
TTLGTextToImage
Seed image — FLUX.1-schnell
Generates a 1024×1024 JPEG from the prompt. Takes ~3 seconds on QB2.
→ image_path
2
TTLGCaptionImage
Describe — BLIP (CPU)
Reads the image and writes a natural-language caption. Runs on CPU, no hardware needed.
→ caption
3
TTLGRemoveBackground
Remove background — RMBG (CPU)
Isolates the foreground into a transparent PNG. Runs on CPU via tenstorrent venv.
→ fg_path
4
TTLGEstimateDepth
Depth map — GLPN (CPU)
Produces a grayscale depth map. Brighter = closer. Useful as a compositing hint.
→ depth_path
5
TTLGPromptCompose
Compose video prompt
Combines the caption with era context to build a richer I2V prompt.
→ video_prompt
6
TTLGImageToVideo
Animate — SkyReels I2V
Turns the seed image into a 97-frame 960×544 video using the composed prompt. ~90s on QB2.
→ video_path
7
TTLGGenerateText
Write poem — Llama-3.3-70B
Llama-3.3-70B writes a 4–6 line poem from the caption. Ready in ~2.5 min on QB2.
→ poem
8
TTLGTextToImage
Poem image — FLUX.1-schnell
Renders the poem as a second image. Same 3-second generation.
→ image2_path
9
TTLGAddToPlaylist
Save to playlist
Imports all artifacts into the app and creates a named playlist. → TT-TV.
→ playlist_id

The JSON format

Workflows are ComfyUI-compatible JSON. Numbered nodes, class_type dispatch, and ["node_id", "output_key"] references for wiring. 

{
  "_description": "image → caption → video → poem → image",
  "_spec_version": "comfyui-api-v1",

  "1": {
    "class_type": "TTLGTextToImage",
    "inputs": {
      "model":  "FLUX.1-schnell",
      "prompt": "The 1964 World's Fair…",
      "seed":   1964
    },
    "outputs": ["image_path"]
  },

  "2": {
    "class_type": "TTLGCaptionImage",
    "inputs": {
      "src": ["1", "image_path"]
    },
    "outputs": ["caption"]
  }
}
Any key that isn't a ["node_id", "key"] reference and matches a known name (prompt, seed, model…) appears as an editable field in the popover — no extra config needed.

Command line

tt-ctl workflow

Everything the UI does is also available from the terminal.

CommandWhat it does
tt-ctl workflow listShow all available workflow specs with descriptions
tt-ctl workflow run <spec.json>Execute a workflow — manages hardware, runs each node
tt-ctl workflow run <spec.json> --dry-runPrint each step without touching hardware

Or call the runner directly with a spec path:

./bin/run_workflow.sh docs/examples/workflows/1964-worlds-fair.json
./bin/run_workflow.sh my-workflow.json --dry-run

Authoring

Write your own workflow

A minimal 2-node workflow that generates an image and captions it.

{
  "_description": "my first workflow → image + caption",
  "_spec_version": "comfyui-api-v1",

  "1": {
    "class_type": "TTLGTextToImage",
    "_comment": "Generate a 1024×1024 JPEG",
    "inputs": {
      "model":              "FLUX.1-schnell",
      "prompt":             "a neon city at night, cinematic",
      "guidance_scale":     3.5,
      "num_inference_steps": 4,
      "seed":               42,
      "server":             "http://localhost:8000"
    },
    "outputs": ["image_path"]
  },

  "2": {
    "class_type": "TTLGCaptionImage",
    "_comment": "Describe the image using BLIP",
    "inputs": {
      "plugin": "blip",
      "src":    ["1", "image_path"]
    },
    "outputs": ["caption"]
  }
}
Save this as ~/.local/share/tt-local-generator/workflows/my-workflow.json and it will appear instantly in the ⚙ Workflow dropdown — no restart needed.

Hardware note

Board resets between steps

FLUX, SkyReels, and Llama-3.3-70B all use different inference stacks on the same QB2 hardware. The workflow runner handles this automatically:

  • CPU plugins (BLIP, RMBG, depth) run any time — no hardware needed
  • Switching between media server models → docker stop + tt-smi -r
  • Switching media server → artgen VLLM → same reset
  • Sequential requests to the same server → no reset
Warmup time: SkyReels I2V takes 20–25 min on first cold start (TTNN kernel compilation). Subsequent starts from cache are ~2 min. The runner starts SkyReels in parallel with CPU plugins to overlap the wait.
